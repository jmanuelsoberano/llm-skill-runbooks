# Preparar una presentación para una audiencia

## Objetivo y alcance

Convierte el contenido y el propósito del usuario en una comunicación adecuada a su audiencia. Puedes orientar, planificar, revisar o producir materiales según el encargo. La serie Never Send The Slides aporta criterios de comunicación; no es una receta universal ni un manual completo de todos los formatos.

Si solo se pide cambiar una fuente, convertir un archivo o corregir una diapositiva, resuelve esa tarea sin abrir este proceso de diseño. Si se invoca explícitamente la skill para un informe autónomo, explica brevemente qué parte del enfoque aplica y ayuda con ese informe; no obligues a transformarlo en charla.

## Entender sin interrogar

Usa primero el mensaje, los adjuntos accesibles y el contexto ya disponible. Identifica el resultado buscado, la audiencia y cómo consumirá el material. Con datos suficientes, empieza sin preguntas.

Cuando falte algo que cambie sustancialmente la entrega, agrupa normalmente hasta tres preguntas breves en una sola ronda:

- ¿Qué deben comprender, decidir o hacer, y quiénes son?
- ¿Habrá exposición en vivo, grabación, lectura autónoma o trabajo conjunto? ¿Cuánto tiempo hay?
- ¿Existe un formato requerido o una restricción decisiva de edición, distribución, acceso o marca?

No repitas respuestas conocidas ni pidas elegir un modo de la skill. Ofrece una recomendación si el usuario no sabe qué formato necesita. Asume detalles reversibles como un estilo sobrio y decláralos brevemente; no supongas hechos, cifras, evidencia ni decisiones aprobadas. Una segunda ronda solo se justifica por una omisión crítica que realmente impida avanzar, no por preferencias estéticas menores.

## Elegir medio y aplicación del enfoque

Separa tres decisiones: propósito de comunicación, forma de consumo y formato de entrega. Un PPTX puede ser un documento visual; un HTML puede ser una charla, un documento o una herramienta interactiva. Respeta el formato que el usuario haya fijado. Si presenta una limitación relevante, explica el ajuste y conserva su elección salvo que acepte otra.

Determina internamente la aplicabilidad y comunícala en una frase solo cuando ayude:

| Aplicación | Criterio | Conducta |
|---|---|---|
| Amplia | Una explicación narrada y los visuales aportan comprensión | Coordina relato, apoyo visual y ritmo. |
| Parcial | Se combinan exposición, discusión, ejercicios o consulta detallada | Combina materiales; permite explorar, preguntar y volver atrás. |
| Fuera del alcance principal | Se necesita lectura autónoma o una edición mecánica | Conserva los principios útiles y sigue el formato solicitado sin imponer narración. |

No conviertas estas categorías en un cuestionario ni uses el tema como sustituto del contexto. Una presentación de arquitectura puede pertenecer a cualquiera de ellas. Para decisiones, distingue el análisis de opciones de su comunicación: reutiliza el brief o la evidencia disponible. Si hace falta analizar la decisión, dilo y atiende ese alcance cuando esté pedido; una skill de decision brief disponible puede ayudar, pero no es una dependencia ni debe invocarse en círculo.

## Construir el material

Formula un mensaje central y una secuencia que la audiencia pueda seguir. Elige la estructura que encaje: explicación, demostración, comparación, propuesta o relato de experiencia. Mantén alternativas, límites, incertidumbres y estado de aprobación; no conviertas persuasión en exageración de resultados.

Para contenido narrado, prepara el storyboard necesario: qué se quiere comunicar, qué se verá y qué aportará la voz. Dosifica la información y reserva tiempo para interacción cuando sea relevante. El relato puede modificarse mientras se diseña; no impongas un número de diapositivas, una duración por lámina o una fórmula de viñetas.

Consulta la guía visual cuando corresponda. Usa gráficos o imágenes que expliquen, texto breve útil, tipografía legible, colores consistentes y espacio suficiente. Presenta código con formato que conserve su estructura. Adapta densidad y tamaño al medio y a la audiencia; respeta marca, atribución, accesibilidad y restricciones reales. Las preferencias del autor por ciertos layouts o por omitir elementos no son obligaciones.

Cuando el contenido deba leerse sin narración, conserva las explicaciones necesarias. Para lectura previa o consulta posterior, prepara el material adecuado si forma parte del encargo; pueden servir un resumen, referencias o notas. No prohíbas compartir diapositivas ni omitas información necesaria para una decisión con el fin de crear sorpresa. Para vídeo, considera pausas y apoyo textual accesible cuando proceda.

## Formato y ejecución

Propón un formato principal y explica en una frase su utilidad. Ofrece como mucho una alternativa relevante, salvo que se solicite comparar más. PPTX favorece edición en herramientas de diapositivas; PDF facilita una entrega fija; HTML permite lectura, navegación o interacción; Markdown o un documento pueden bastar para contenido autónomo. Son criterios de elección, no garantías de capacidades del agente.

Comprueba qué herramientas existen antes de prometer exportación o publicación. Si se pidió generar y el entorno lo permite, crea el artefacto. Reutiliza herramientas o skills especializadas disponibles para producirlo; este procedimiento no sustituye sus mecanismos de renderizado. No añadas servicios, cuentas o frameworks si una entrega sencilla resuelve la necesidad. Un HTML local no requiere publicarse: respeta conectividad y funcionamiento sin conexión cuando se pidan.

Si el formato solicitado no se puede generar, comunica la limitación concreta y ofrece una salida utilizable, por ejemplo contenido estructurado, HTML o instrucciones de exportación. Identifica esa salida como alternativa o material pendiente de exportar; no llames PPTX a texto Markdown ni afirmes que una exportación se verificó sin abrirla.

## Verificar y cerrar

Comprueba el resultado frente a audiencia, propósito, fidelidad a la evidencia y forma de consumo. En archivos, revisa visualmente el renderizado o vista previa cuando haya herramientas: recortes, contraste, legibilidad, notas y coherencia. Para HTML, prueba navegación y funciones relevantes; si se exige offline, comprueba sus dependencias. En una exposición, estima el tiempo como estimación y sugiere ensayo cuando aporte; no lo presentes como tiempo medido.

Entrega lo pedido sin un informe metodológico adicional. Menciona solo decisiones y supuestos importantes, el material generado y verificaciones realizadas o pendientes. Usa español salvo preferencia distinta e inglés para identificadores técnicos. No actualices el catálogo ni programes revisiones de fuentes como efecto secundario de preparar una presentación.
