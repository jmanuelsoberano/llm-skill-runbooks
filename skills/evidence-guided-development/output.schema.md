# Contrato de salida

Entrega el artefacto que pide el usuario y adapta la extensión a la tarea. Usa español por defecto e inglés para identificadores, código y nombres de archivos. Respeta las plantillas del proyecto. No impongas un informe de arquitectura a todas las tareas.

| Trabajo solicitado | Resultado y evidencia mínima |
|---|---|
| Análisis o planificación | Recomendación o plan, contexto, supuestos, alternativas cuando aporten, riesgos y validación propuesta. |
| Implementación o refactorización | Cambios concretos en el código, pruebas pertinentes y resumen de qué cambió, por qué, qué se verificó y qué falta. Si no hay archivos accesibles, entrega un ejemplo o propuesta e identifica esa limitación. |
| Revisión de código o diseño | Hallazgos accionables con ubicación y severidad cuando corresponda, evidencia, impacto y corrección sugerida. No apliques correcciones si solo se pidió revisión. |
| HU y requisitos | Historia orientada al valor, reglas confirmadas, criterios de aceptación verificables, ejemplos/excepciones, dependencias y preguntas abiertas. Usa el formato existente y evita inventar política de negocio. |
| Documentación | Documento o actualización solicitados, coherentes con el sistema y sus decisiones; ejemplos y referencias cuando sean útiles. |
| Cambio trivial | Cambio y confirmación breve; sin informe ni investigación extensa. |

En decisiones sustantivas, relaciona evidencia, interpretación, acción y comprobación mediante prosa o tabla. Distingue hechos medidos, hechos reportados, inferencias y propuestas. Cita las fuentes junto a las afirmaciones que respaldan; identifica como lecturas pendientes los materiales solo localizados.

No atribuyas contenido a un libro sin haber leído la sección pertinente. No presentes una prueba propuesta como ejecutada, una mejora esperada como medida o un plan como implementación terminada. Si una capacidad ausente afecta a la entrega, explica el alcance pendiente sin bloquear trabajo independiente.

Cuando aporte trazabilidad, acompañar las decisiones sustantivas con IDs y el registro de references/evidence-contract.md: procedencia, acceso, respaldo/contradicción/matiz, ubicación y aplicabilidad. Esta evidencia complementa el artefacto solicitado; no impone secciones nuevas a cambios triviales ni sustituye código, pruebas, HU o documentación por un informe universal.
