# Contrato de salida

Adapta extensión y formato al usuario o a la plantilla del proyecto. Mantén los elementos del contrato dentro de ese formato, sin crear secciones vacías ni un informe universal. Usa español y conserva identificadores técnicos en inglés. Integra referencias con identificadores junto a la conclusión que sostienen. Señala límites de acceso y distingue resultados observados de verificaciones pendientes.

## Contenido del diseño

- Significado, invariantes y contratos afectados.
- Estado actual conocido y supuestos pendientes.
- Diseño del cambio y compatibilidad de versiones/consumidores.
- Secuencia de transición y backfill cuando aplique.
- Validaciones antes/después, reconciliación y comportamiento ante fallos.
- Riesgos operativos, observación y condiciones de pausa.
- Recuperación, límites de reversibilidad y entorno autorizado.

Para cambios pequeños, integra los elementos relevantes en un plan breve. Scripts o código preparados se distinguen de migraciones ejecutadas. No contiene resultados de datos o ensayos que no se hayan obtenido.
