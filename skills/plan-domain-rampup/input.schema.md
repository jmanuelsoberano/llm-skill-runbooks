# Contrato de entrada

Acepta contexto de incorporación, tarea inicial, repositorio, documentación, diagramas, tickets, conversaciones o archivos adjuntos.

## Mínimo
Dominio/sistema concreto y responsabilidad que se desea asumir, o información para deducir una primera ruta.

## Contexto útil
Experiencia, acceso, tiempo, miembros/owners conocidos, entregables esperados, flujos críticos, operación, entorno local y reglas documentadas.

Si solo hay una tecnología sin sistema concreto, orientar al aprendizaje técnico. Si falta acceso a un artefacto, registra el bloqueo y diseña la actividad pendiente; no inventes arquitectura ni owners.
