# Checklist de evaluación

## Entrada

- [ ] Identifica el tipo de repositorio.
- [ ] Usa el propósito indicado por el usuario.
- [ ] Marca información faltante.

## Estructura

- [ ] Propone carpetas necesarias.
- [ ] Evita complejidad innecesaria.
- [ ] Explica para qué sirve cada archivo base.

## Documentación

- [ ] Incluye contexto del proyecto.
- [ ] Incluye registro de decisiones.
- [ ] Incluye pendientes iniciales.
- [ ] Incluye changelog.

## Calidad

- [ ] No inventa tecnologías.
- [ ] No mezcla decisiones con tareas.
- [ ] Sugiere primer commit.
- [ ] La salida se puede reutilizar como documentación inicial.
