# Output schema

La salida debe ser un documento Markdown autocontenido.

## Secciones obligatorias

1. Título de la reunión.
2. Resumen ejecutivo.
3. Contexto general.
4. Participantes identificados.
5. Temas principales tratados.
6. Decisiones tomadas.
7. Compromisos, tareas y acciones pendientes.
8. Preguntas abiertas y puntos por confirmar.
9. Riesgos, bloqueos y dependencias.
10. Requerimientos identificados.
11. Posibles issues o tickets para repositorio.
12. Implicaciones técnicas o para repositorio.
13. Línea de tiempo de la reunión.
14. Información útil para documentación futura.
15. Glosario de términos, sistemas y entidades.
16. Análisis de “lo que realmente se quiso decir”.
17. Siguientes pasos recomendados.
18. Resumen ultra breve.
19. Calidad del transcript y confiabilidad del análisis.

## Valores controlados

### Nivel de certeza

- Alta
- Media
- Baja

### Prioridad sugerida

- Alta
- Media
- Baja

### Estado sugerido

- Pendiente
- En progreso
- Requiere confirmación
- Bloqueado
- Completado

### Tipo de issue

- Bug
- Feature
- Mejora
- Documentación
- Investigación
- Tarea operativa
- Requiere análisis

## Reglas de salida

- No inventar información.
- Marcar inferencias como `Inferencia`.
- Usar `No especificado` cuando falten datos.
- Usar tablas para decisiones, compromisos, riesgos y requerimientos.
- Mantener el resultado útil para alguien que no asistió.
