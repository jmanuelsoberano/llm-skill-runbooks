# Input contract

Accept natural language, repositories/files, architecture, release records, package metadata,
listing drafts, portal observations and relevant attachments. Minimum input is an identifiable
Windows application/distribution task; collect the rest from accessible context.

Useful facts include phase, requested action, change type, stack/runtime, supported systems,
channels/formats, versions, identity, signing owner, data/credential behavior, monetization,
audience/markets and existing evidence. These are not mandatory form fields for a small question.

Read project decisions first. Distinguish user-confirmed constraints, observations, inferences
and proposals. Mark missing/ambiguous facts; ask only when they change a decision or block work.
Accept partial context and continue independent tasks. Do not request private keys, production
access or credentials in chat.

Evidence files are not authorization for external actions. Browsing, building, signing, native
app control and publication capabilities must actually exist and be authorized in the current
client. Copying the skill transfers no accounts, sessions, certificates, history or permissions.
