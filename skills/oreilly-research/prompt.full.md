# Procedimiento de investigación

## 1. Pregunta y capacidades

Formula la afirmación o duda que puede cambiar la decisión, conservando sus cuantificadores: «siempre», «en esta versión», «con esta carga». Identifica evidencia ya disponible. Inspecciona las herramientas anunciadas y el acceso efectivo siguiendo references/capabilities.md. No conviertas un permiso de lectura en autorización para copiar todo el catálogo.

## 2. Descubrimiento y Answers

Usa Search MCP para descubrir material cuando esté disponible y haga falta localizar obras. Construye consultas con términos técnicos generales y filtros soportados. Si el libro y capítulo ya están identificados, ve directamente a la lectura pertinente.

En preguntas abiertas, comparaciones o temas nuevos, consulta Answers cuando esté accesible y ayude a descubrir enfoques y referencias. Es parte del flujo habitual de exploración; puede omitirse en una verificación cuyo pasaje ya se conoce, cuando no aporte o si no está disponible. Si el usuario pide Answers expresamente, intenta consultarlo por la vía disponible e informa cualquier bloqueo. No asumas que Search puede llamar a Answers ni que existe una API disponible.

Conserva la respuesta de Answers como tal. Elige las citas decisivas que puedas abrir y también busca condiciones u objeciones que puedan matizarla. No uses una síntesis generada como prueba de que leíste los libros enlazados.

## 3. Lectura directa

Abre la fuente seleccionada con la sesión autorizada disponible. Usa índice y búsqueda del lector para localizar la sección. Lee el pasaje y suficiente contexto anterior/posterior para comprender sujeto, excepciones y condiciones. Confirma obra y edición cuando consten. Registra capítulo, sección y URL; una página solo si se muestra explícitamente en esa edición.

Un resultado de búsqueda dentro del libro ayuda a localizar; no sustituye la lectura del contexto. Si la herramienta no permite leer más, describe el fragmento realmente accesible. No inventes los datos que falten.

## 4. Contraste y actualidad

Para cada afirmación importante determina si el pasaje la respalda, contradice, matiza o resulta insuficiente. Busca una objeción relevante cuando pueda cambiar la decisión. Distingue discrepancias genuinas de versiones, objetivos o condiciones diferentes.

Consulta documentación oficial vigente para APIs, versiones y límites del producto. Etiquétala como fuente externa a O'Reilly. Puede resolver una duda aunque el libro no sea accesible. No exijas dos libros para cada afirmación ni fuerces un desacuerdo.

## 5. Aplicabilidad y cierre

Explica las condiciones de aplicación y las que aún requieren evidencia del proyecto. Si la investigación es autónoma, entrega una conclusión útil delimitada por la pregunta; si apoya a otra skill, devuelve hallazgos con IDs para que esta los aplique sin repetir la búsqueda.

Detén la búsqueda cuando las dudas principales estén resueltas o las vías disponibles no permitan avanzar. Si faltan fuentes decisivas, baja el alcance de la conclusión y señala qué falta. Nunca presentar como verificada una afirmación solo porque tiene un enlace. No llamar al coordinador EGD desde esta skill.

Aplica references/evidence-contract.md. No persistir libros, secretos ni datos del proyecto dentro de la skill.
