# Proceso de revisión de prompts

## 1. Contexto del cambio

Documenta:

- por qué se cambia;
- qué problema corrige;
- qué usuarios afecta.

## 2. Tipo de cambio

- Patch
- Minor
- Major

## 3. Revisión de contrato

Verifica:

- entrada;
- salida;
- valores controlados;
- secciones obligatorias.

## 4. Pruebas

Ejecuta:

- ejemplo básico;
- ejemplo ambiguo;
- caso real;
- evaluación con checklist.

## 5. Changelog

Toda modificación aceptada debe actualizar `changelog.md`.

## 6. Criterios de aceptación

El cambio debe mejorar utilidad sin reducir confiabilidad.
